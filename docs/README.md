# Building the documentation

The documentation is built with [**mystmd**](https://mystmd.org) (the engine
behind Jupyter Book 2). It replaced the old Sphinx-based Jupyter Book v1 setup
(`_config.yml` + `_toc.yml`), which is why there is no `conf.py` anymore.

## One-time setup

You need the doc toolchain: `mystmd` (a Node package) plus the Python helpers
that generate the API reference (`numpydoc`), and seaduck itself installed so
its docstrings and notebooks can be imported/executed.

The easiest route is the CI environment, which now includes all of these:

```shell
conda env update -f ci/environment-ci.yml
conda env update -f environment.yml
pip install --no-deps -e .
```

Check it worked:

```shell
myst --version      # should print v1.x
```

## Build the site

From the repository root:

```shell
make docs-build
```

This does two things:

1. **`make docs-api`** — runs `docs/generate_api.py`, which reads the
   docstrings out of `seaduck/*.py` and writes the API-reference pages into
   `docs/api/*.md`. These files are **build artifacts**: they are git-ignored
   and regenerated every time, so never edit them by hand — edit the
   docstrings in the Python source instead.
2. **`myst build --html --execute`** — builds the static HTML site into
   `docs/_build/html/`. The `--execute` flag runs every notebook so that the
   plots and other cell outputs actually appear. (Without it the build is much
   faster but the notebooks render with no figures.)

## Live preview while editing

```shell
make docs-serve
```

This starts a live-reloading server at <http://localhost:3000>. It also runs
notebooks (`--execute`), so figures show up. Edit a Markdown file and the page
refreshes automatically. Stop it with `Ctrl-C`.

> Tip: if you are only tweaking narrative text and don't need the notebook
> figures, you can run the faster `cd docs && myst start` (no `--execute`)
> directly.

## Checking links

```shell
make link-check
```

Some sites block link-checkers, so an occasional false positive is expected —
open the URL in a browser to confirm before treating it as broken.

## Notes / known issues

- **Two images in `docs/sciserver_notebooks/LLC4320.md` fail to load.** They
  point at `...?raw=true` GitHub blob URLs that return the wrong content-type.
  The `sciserver_notebooks/*.md` files are generated by a separate repository's
  script, so this is fixed upstream, not here.
- The build intentionally does **not** run in `--strict` mode, so the broken
  images above (and similar external-asset hiccups) do not fail the build.
- The old `docs/_config.yml`, `docs/_toc.yml`, and `docs/api_reference/*.rst`
  files are leftovers from the Sphinx setup and can be removed once the
  migration is finalized.
